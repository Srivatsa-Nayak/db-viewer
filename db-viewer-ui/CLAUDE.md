# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # start dev server (http://localhost:3000)
npm run build    # production build
npm run start    # run production build
npm run lint     # eslint (flat config in eslint.config.mjs)
```

There is no test suite in this repo. There is no single-file lint/typecheck shortcut beyond `npm run lint`; use `npx tsc --noEmit` for a type-only check.

The backend (sibling directory `../db-viewer-backend`, Spring Boot / Java 17) must be running on port 8080 for the UI to do anything useful: `./mvnw spring-boot:run` (or `mvnw.cmd spring-boot:run` on Windows) from that directory. Swagger UI is at `http://localhost:8080/swagger-ui.html`.

## Environment

The backend base URL comes from `NEXT_PUBLIC_API_URL`, falling back to `http://localhost:8080` (`services/api.ts`). Env files present: `.env.local`, `.env.production`.

## Architecture

This is a Next.js (App Router) single-page workspace app for importing CSV/SQL files, visualizing schema as a graph, editing table data, and exporting. There is no in-app SQL query runner — that panel (`SqlEditor`/`ResultsTable`/`useQuery`, plus `dbService.runQuery`/`POST /query`) was removed; if it needs to come back, it must be re-added as a sibling of the canvas, not nested inside `Visualizer.tsx`. Nearly all state lives in one place:

- **Routes:** `/` is the landing page (`app/page.tsx` — marketing only, no workspace state), `/app` is the editor (`app/app/page.tsx`), `/share/[token]` is the read-only shared view. Anything below describing "the page" means the **editor** at `app/app/page.tsx`.
- **Templates are backend-owned.** `GET /templates` returns the catalogue; `components/landing/TemplatesSection.tsx` only renders it. Adding a template is a backend-only change (a `.sql` file plus a `manifest.json` entry) — do not hardcode template metadata in the frontend. The landing page starts a template by creating a workspace, calling `POST /templates/{id}/apply`, appending to the stored session and pushing to `/app`; the editor's existing restore path does the rest.
- **`app/app/page.tsx`** is the owner of almost everything: `workspaces`, `activeWorkspaceId`, explorer open state, table-editing state, and upload/clear/notice/info modal state. `refreshActiveSchema` is intentionally `useCallback(..., [])` and reads `activeWorkspaceIdRef.current` — every node captures it in `data.onRefresh`, and a closure over the `activeWorkspaceId` *state* is stale for a freshly created file (it is still the previous id, `null` for the first file), which made the canvas silently not update after a column edit. Don't add dependencies to it. It also contains the schema→React-Flow transform (`transformSchemaToWorkspace`) and refresh logic. Start here for any workspace-level behavior change.
- **Workspaces are backend-isolated.** Each open file's `id` *is* a backend workspace id, sent on every request as the `X-Workspace-Id` header (see `services/api.ts`), and the backend keeps a separate database per id. Two files can define the same table names. `setActiveWorkspace()` is called both from a `useEffect` on `activeWorkspaceId` **and synchronously** in `handleFileUpload`/`handleCreateBlankFile` — the synchronous call is load-bearing, because those two generate an id and call the API in the same tick, before the effect runs. Workspace ids come from `services/workspaceId.ts` (`newWorkspaceId()`), never `Date.now()` — two files created in the same millisecond used to collide onto a single backend database.
- **`services/api.ts`** centralizes every backend call (`dbService`) **and normalizes the wire format**. The backend has shipped both `is_pk` and `isPk` (and `source_table`/`sourceTable`, `not_null`/`notNull`); `normaliseColumn` / `normaliseRelationships` / `normaliseSchema` fold both spellings into the camelCase shapes in `types/index.ts` at the boundary, so no component should ever write `c.is_pk ?? c.isPk` again. Normalize new response-reading endpoints here too. Endpoints: `POST /upload`, `POST /alter-table`, `GET /db-info`, `GET /export/{tableName}`, `GET /table-data/{tableName}`, `POST /update-cell`, `POST /insert-row`, `POST /delete-row`, `DELETE /workspace`, `GET /export-sql`, `POST /create-table`, `POST /update-column`, `GET /version`, `GET /workspaces`, `DELETE /table/{name}`, `POST /demo`, `/table-notes...`, `/auth/*`, `/share*`, `GET /templates`, `GET /templates/{id}`, `POST /templates/{id}/apply`. Exports go through Axios as blobs, not `<a href>`, because a link cannot carry the `Authorization` header those endpoints now require. `uploadFile` returns an `UploadReport` (`statementsExecuted`/`statementsSkipped`/`warnings`) — surface it via `NoticeModal`, don't drop it. Most cache-sensitive reads append a `_t`/`t` timestamp query param to bust caching.
- **Session persistence** lives in `services/sessionStorage.ts` (localStorage key `sql-visualizer.session`). It stores only ids, filenames and node positions — never the schema, which is always re-fetched from the backend on restore so it cannot go stale. `page.tsx` reconciles the stored list against `GET /workspaces` and drops entries whose database is gone; if the backend is unreachable it *keeps* the stored session rather than clearing it. Saving is debounced 300ms because node dragging fires `onNodesChange` continuously, and it is skipped while `isRestoring` so the first render cannot overwrite storage with an empty list.
- **Workspaces are owned, and the ownership is enforced by a filter.** Every workspace belongs to `user:<email>` (signed in) or `anon:<clientId>` (signed out), recorded in `workspace_owners` in the *default* database. `WorkspaceOwnershipFilter` claims a workspace for the first identified caller to touch it and answers 403 (`notYourWorkspace: true`) to anyone else, so a new endpoint is covered the moment it is written. `GET /workspaces` is scoped to the caller. The browser's identity comes from `X-Client-Id` (`services/clientId.ts`, localStorage), sent on every request beside `X-Workspace-Id`. On sign-in/sign-up the backend re-keys that browser's anonymous workspaces onto the account, so making an account does not strand the work that led to it — and it only ever moves workspaces that are *still* anonymous, so a second user on a shared browser cannot inherit the first one's files. **Signing out clears the open-files list** in the UI, because those workspaces would now 403. Handle 403 with `isForeignWorkspace(e)`, not `isAuthRequired(e)`: the caller is identified fine and signing in again would not help.
- **`CorsFilter` runs at `HIGHEST_PRECEDENCE`, ahead of every application filter.** Ordering is load-bearing, not tidiness: `WorkspaceOwnershipFilter` short-circuits with 403, and a response that never reaches the CORS filter carries no `Access-Control-Allow-Origin` — the browser then refuses to show the body, so the frontend sees an opaque network failure instead of a 403 it knows how to explain. Any new short-circuiting filter inherits this constraint.
- **Accounts are optional but enforced server-side.** Everything works signed out except exporting and creating a share link, which return 401. Gate in the UI *and* let the backend reject — `isAuthRequired(e)` turns a 401 into the sign-up prompt. Callbacks stored in node `data` (e.g. `handleDownloadCsv`) must read `userRef.current`, never the `user` state, or they pin to the first render's `null`.
- **A React Flow edge needs a `Handle` on both ends or it silently does not render.** The shared-file page (`app/share/[token]/page.tsx`) has its own read-only node, and originally drew no handles at all - so relationship lines never appeared even though the API returned them. It now derives the required `sourceColumns`/`targetColumns` per table from the relationships themselves (not from `*_id` naming like `TableNode` does) and sets `sourceHandle`/`targetHandle` on every edge. Any new custom node that edges attach to must do the same.
- **`services/exportImage.ts`** renders the canvas to PNG. It sizes the image from `getRectOfNodes` rather than the visible pane, so the export is not clipped to whatever is on screen.
- **`types/index.ts`** holds the shared types (`ColumnInfo`, `TableInfo`, `Relationship`, `SchemaResponse`, `TableDataResponse`) **plus the `Raw*` wire shapes**. The normalized types *are* ground truth now, because `services/api.ts` guarantees them; the `Raw*` types should be imported only by `services/api.ts`.
- **`components/canvas/Visualizer.tsx`** + **`components/tables/TableNode.tsx`**: the React Flow schema canvas, light-theme only (the dark/system toggle was removed — it only ever restyled the canvas/table nodes, never the rest of the chrome, and looked inconsistent). `TableNode` decides which columns get *handles* from `isKeyColumn()`: real `isPk` metadata **or** the `id` / `*_id` naming convention. The naming heuristic is still there because a foreign key column is only identifiable that way without reading the relationship list, but a real primary key no longer depends on being called `id`. The canvas is deliberately **not** connectable (`nodesConnectable={false}`, and every `Handle` sets `isConnectable={false}`): the old no-op `onConnect`/`onEdgesChange` meant dragging a handle started a connection gesture the app could not honour. Relationships are created through `CreateTableModal`'s FK fields, which do persist. If drag-to-create is ever built, re-enable connectability *and* wire it to a backend call in the same change.
- **Every dialog goes through `components/ui/Modal.tsx`.** Do not hand-roll another overlay. The primitive owns the portal (always — a `position: fixed` descendant of React Flow's transformed viewport anchors to the canvas pane, not the window), Escape-closes only the top of the dialog stack, traps and restores focus, locks body scroll, sets `role="dialog"` / `aria-modal` / `aria-labelledby`, and derives its z-index from stack depth so nested dialogs never need a hand-picked `z-[130]`. It ships `ModalActions`, `PrimaryButton`, `DangerButton`, `GhostButton` and `Callout` for the furniture, and `components/ui/ConfirmDialog.tsx` for destructive confirmations. Below `sm` a dialog becomes a bottom sheet.
- **Dialogs are mounted only while open** (`{isOpen && <Foo isOpen ... />}`) and imported with `next/dynamic` + `ssr: false`. That is load-bearing twice: it keeps them out of the initial bundle, and it means *mounting is the reset* — which is why none of them re-seed form state from a `useEffect` any more, and why the old `key`-bumping remount trick is gone.
- **`components/modal/`**: `NewFileModal` (name a new file), `CreateTableModal` (full definition incl. FKs; one column per field below `lg`), `AddColumnModal` (single `ALTER TABLE`, opened from a table node's `+`), `EditColumnModal` (rename/retype, opened from the pencil on a column row — sends only the fields that changed, so a no-op save doesn't trigger a SQLite table rebuild), `NoticeModal` (error/warning with collapsible details, used for import reports), `InfoModal` (header help button: five-line app summary, version badge from `GET /version`, and developer credits — keep it to a glance, not a manual), `NewTableHelpModal` (canvas toolbar info button: what the New Table button does). The last two are intentionally *not* the same modal — help for a specific control belongs beside that control, the app summary belongs in the header.
- **`components/editor/DataEditor.tsx`**: row view/add/delete dialog with two editing modes — click a cell for a quick single-cell edit, or the row's pencil to edit every field at once with Save/Cancel (one `update-cell` per changed field; a partial failure names the fields that *were* written). A cell edit has exactly **one** commit path: `onBlur`. Enter and Escape both just call `blur()`, and Escape sets `abandonEditRef` so the blur skips the write — do not add a second commit to the key handler, which is what used to fire a duplicate `update-cell` on every Enter. Rows are keyed by their own `id`, never by array index. Update/delete paths assume every row has an `id` or `ID` field; a row without one has its buttons disabled rather than silently doing nothing.
- **Styling**: Tailwind v4, configured entirely from `app/globals.css` (there is no `tailwind.config.js`; the vestigial one pointing at `./src/**` was deleted). One palette for the whole product, declared in the `@theme` block: **`brand-*`** (blue 50-900 plus `brand-violet`) and **`ink-*`** (slate-valued neutrals 50-950), plus `surface`, `surface-tint`, `line`. Use those rather than raw `blue-*` / `zinc-*` / `slate-*` — the landing page and the editor used to run on two different systems, which is what made them read as two apps. Shared utilities: `brand-gradient(-hover)`, `brand-text-gradient`, `surface-card`, `section-wash(-tinted)`, `shadow-glow-sm/md/lg`, `scroll-slim`, and the `anim-*` animations. **There is no `tailwindcss-animate` plugin** — `animate-in` / `fade-in` / `slide-in-from-*` were inert at 17 call sites; use `anim-fade-in`, `anim-fade-up`, `anim-dialog-in`, `anim-menu-in`. An extra `xs` breakpoint (25rem) exists because Tailwind's smallest default is 640px. Light theme only, and the dead `.dark` scaffolding has been removed.
- **Responsive layout**: the editor shell is `h-[100dvh]`, not `h-screen` (mobile browser chrome). `FileExplorer` is a persistent column from `lg` up and an **overlay drawer** below it — absolutely positioned inside the `relative` content row, with a scrim rendered by `app/app/page.tsx`; selecting a file closes it on narrow screens. Its collapsed 48px rail is the only way back, so it renders at every width. The data table is the one element allowed to scroll sideways. Hover-only affordances (row actions, note delete) are `opacity-100` by default and only hover-gated from `sm` up, because touch has no hover.
- **Fonts**: two faces, both via `next/font/google` in `app/layout.tsx`. **Inter** drives `--font-sans` and the `body` rule — it is the UI face, and `globals.css` pairs it with the negative tracking and `cv02/cv03/cv04/cv11` features it is designed to be read with. **Geist Mono** drives `--font-mono`, so every `font-mono` utility (table/column names, filenames, zoom %, inline code in the docs) picks it up automatically. Keep monospace content on `font-mono` — column alignment depends on it — and don't hardcode a font-family per component.

## Suggested change workflow

1. Start from `app/app/page.tsx` for anything workspace-level; `app/page.tsx` is the landing page.
2. Check `services/api.ts` before adding/changing a backend call, and confirm the endpoint exists on the backend side (`../db-viewer-backend`, controllers under `src/main/java/com/dbviewer/app/controller/`).
3. Update `types/index.ts` when relying on new backend response fields.
4. New dialog? Use `components/ui/Modal.tsx`. New colour? Use a `brand-*` / `ink-*` token. New password input? Use `components/ui/PasswordField.tsx` (it carries the reveal toggle).
5. Run `npx tsc --noEmit`, `npm run lint`, and `npm run build` after TypeScript/component edits. The lint config is strict about `react-hooks/set-state-in-effect` and `react-hooks/refs`; both usually mean the state should be derived, or the component should be mounted conditionally instead.
